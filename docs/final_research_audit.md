# Final Research Audit

## 1. Experimental Integrity
The integrity of the research pipeline has been thoroughly verified:
* **Phase 4.5 baseline integrity:** The original Phase 4.5 multi-seed baseline experiment remains entirely unchanged.
* **Phase 7 baseline integrity:** The original Phase 7 causal routing evaluation remains unchanged. The Model D evaluation was strictly separated into `phase7_model_d`.
* **Causality and Leakage:** Strict temporal causality is maintained throughout the pipeline. The `TemporalGraphDataset` enforces chronological 70/15/15 splits. Normalization scalers are fitted exclusively on training splits. Phase 7 evaluation processes traffic and routing decisions sequentially, strictly enforcing that decisions at time $t$ only have access to telemetry completed by time $t-1$. No future leakage exists.
* **Controlled Comparisons:** The GA configuration (population, elitism, mutation, generation count, and objective weights) was kept perfectly identical across all routing methods to ensure isolated evaluation of the forecasting models. Both Phase 7 experiments used the exact same simulator seed, topology, demand sequences, and flow mappings.
* **Code Modification:** No source data generation files were modified to skew results. Model D was evaluated using correctly frozen checkpoints chosen strictly by validation loss, without any Phase 7 retraining.
* **Security Sub-project separation:** The UNSW-NB15 dataset is used for independent anomaly detection (Phase 5). Because a scientifically rigorous flow-to-SDN-directed-link mapping does not yet exist, security has intentionally not been artificially injected into the QoS routing evaluation, preserving the scientific validity of the QoS pipeline.

## 2. The Model D Negative Result
Model D implemented a learned scalar temporal self-attention over the history of the GRU hidden states. 
* **Result Statement:** Model D produced a small improvement in aggregate forecasting MAE over Model B, but this improvement did not transfer to downstream proactive routing performance.
* **Detailed observation:** Model D showed slightly lower MAE in `increasing_load` and `congestion` scenarios. However, in Phase 7 routing, Model D demonstrated higher packet loss and higher average delay compared to Model B, and crucially, it introduced routing failures (2 failed flows) where Model B had none. This indicates that the attention mechanism smoothed the forecasting thresholds, degrading the GA's ability to avoid hard capacity constraints. This negative result is scientifically valid and well-documented.

## 3. Final Proposed Pipeline
The empirically supported primary routing pipeline is:
1. Synthetic SDN telemetry generation 
2. **Model B spatiotemporal GNN** (EdgeQoSForecaster)
3. Predicted QoS extraction
4. QoS-aware Genetic Algorithm (GA) Path Optimization
5. Proactive routing decision application
6. SDN simulator performance evaluation

## 4. Final Research Limitations
Honest acknowledgment of research limitations is critical:
* **Synthetic Telemetry:** The QoS telemetry is generated by a deterministic simulator, not recorded from a physical network.
* **Absence of Real-World Deployment:** The architecture has not yet been validated on a live SDN testbed (e.g., using Mininet, Ryu, and OpenFlow switches).
* **Simplified Simulation Mechanics:** The custom Python SDN simulator uses fluid-like flow capacities and deterministic queues; it does not model packet-level scheduling, TCP window scaling, or retransmission dynamics in full detail.
* **Security Integration:** The security component uses the UNSW-NB15 dataset. However, mapping arbitrary offline PCAP flow data to the specific synthetic directed links of this simulation remains an open challenge. Currently, the Random Forest security score acts as an uncalibrated risk probability rather than a fully integrated real-time SDN routing metric.
* **Mismatch between Regression and Routing:** The Model D evaluation starkly highlighted that an improvement in forecasting regression metrics (MAE) does not guarantee an improvement in downstream routing decisions, due to the high sensitivity of routing to specific capacity boundary crossings.
* **Topological Constraint:** The experiments used a fixed topology seed. Generalization to entirely different, vastly larger, or dynamic topologies requires future research.
* **Statistical Power:** Comparisons were generally made across 3 training seeds. No strong claims of statistical significance are made for small percentage differences without extensive multi-seed/multi-topology hypothesis testing.
