# GEANT h96 DG-STMTL-based baseline — candidate protocol v1

**State: implemented for synthetic review; real-data preflight/training disabled pending independent review.** No DG-STMTL training results are available from this implementation task.

## Research scope and fairness contract

This experiment asks whether a single-target, edge-centric adaptation inspired by DG-STMTL improves 96-step-ahead GEANT computed directed-link utilization forecasts. It uses the existing verified h96 train/validation stream and does not rebuild data or change preprocessing. Its required input/target contract is the same as the current h96 GNN experiments: 672 historical samples, one target at `origin + 96`, 72 directed-link columns in the exact verified topology order, train `[0,8020)`, validation `[8020,9740)`, 3,924 train windows, and 953 validation windows. The official test interval is not selected, loaded, or used.

The primary comparison is the already-completed topology, identity, and shuffled GNN runs for seeds 42, 123, and 2026, plus EWMA alpha 0.8. Those runs are not retrained or edited. DG-STMTL-based runs use the same train/validation stream, training-only window-occurrence-weighted scaler, batch size 4, Adam at 0.005, maximum 20 epochs, patience 4, SmoothL1 beta 0.001 on original-unit residuals, and validation residual SmoothL1 for checkpoint selection. This matches the current h96 v2 comparison budget; it does **not** claim identical optimization dynamics because the architectures and parameter counts differ. All three DG runs use CPU, deterministic seed setup where supported, and the same graph construction.

MAE and RMSE are computed in computed-utilization-ratio units over finite, aligned `(validation origin, directed link)` pairs. Existing h96 window validation excludes invalid source/target windows before model inputs. No metric-time clipping, imputation, or per-method mask selection is allowed. Expected coverage is 953 × 72 = 68,616 pairs per method. The report script requires identical dataset metadata hash, training normalization, ordered edge digest, validation window count, and pair count before comparing. Three-seed mean and sample standard deviation (`ddof=1`) describe seed variability, not a confidence interval. No comparison outcome is known yet.

## Paper mechanisms and adaptation ledger

Reference: Cui, Wang, and Yin, “DG-STMTL: A Novel Graph Convolutional Network for Multi-Task Spatio-Temporal Traffic Forecasting,” arXiv:2504.07822v2. The paper describes (i) a hybrid prior/dynamic adjacency with task-specific multiplicative gate, (ii) a cross-task knowledge-exchange unit that derives dynamic adjacency from temporally pooled task features, and (iii) a two-stage group-wise spatio-temporal graph convolution. See [Sections 4.2–4.4 and equations 2–16](https://arxiv.org/html/2504.07822#S4) and its [single/multi-task setup and experiments](https://arxiv.org/html/2504.07822#S5). The paper reports 12 historical steps and up to 200 epochs/patience 10 in its own settings, on PeMS and NYC datasets; those results and settings are not directly transferable to this 672-step GEANT task.

| Paper element | This candidate | Classification |
|---|---|---|
| Static physical/spatio-temporal prior plus dynamic adjacency | Static topology is the link line graph: two directed-link vertices connect when their endpoint sets intersect (including reverse directions). A three-temporal-slot prior lifts that graph with same-link adjacent-time edges and cross-time line-graph edges. Dynamic adjacency is sample-conditioned from input-only temporal tokens through max pooling, a learned projection, dot-product correlation, and row softmax. | Adapted: paper's physical node graph becomes an edge/link graph; paper does not fully specify `F(A_S,A_T,A_ST)`, so our binary union is an explicit implementation choice, not its recovered exact formula. |
| Task-specific multiplicative gate `M_k ⊙ (A_P+B)` | One learned 216×216 gate is used for the one available utilization target. It is sigmoid-constrained and the resulting hybrid matrix is row-normalized for numerical stability. | Adapted: one target means one gate; sigmoid constraint and row normalization are implementation choices beyond the paper's displayed equation. |
| CTKE task/spatial/temporal embeddings and dynamic correlation | Learnable link and temporal-position embeddings are added to the encoded input tokens; the pooled features create a per-sample dynamic graph. | Adapted: task embeddings collapse to a single task; there is no cross-task exchange. The adjacency is input-conditioned without reading labels or future values. |
| Three temporal grouping stages and group-wise GCN-AGG | The 672 samples are encoded in twelve non-overlapping 56-sample learned patches. Four consecutive groups of three tokens each pass through three GCN-AGG layers with weighted softmax residual fusion and center-slot cropping. The four resulting groups are regrouped as `(1,2,3)` and `(2,3,4)`, passed through a second three-layer group block, and max-pooled. | Adapted: group/crop/regroup operations follow the paper's two-stage pattern; 672→12 patch compression is required for tractability and differs from its 12-step input. Link-level graph vertices replace road sensors. |
| Multi-task target-specific input, cross-task integration/output and weighted task losses | One shared input path and one h96 residual output are used. | Omitted: the approved dataset has one target only; no second target labels are introduced or fabricated. |
| Paper's training/evaluation setup | Same fixed h96 comparison budget as the existing GEANT v2 runs; same training-only scaler, EWMA residual target, validation selection, and MAE/RMSE. | Adapted: paper's 12-step, multi-task PeMS/NYC protocol is not copied. No paper-reported score is used as a GEANT comparator. |

Accordingly, the model is called **DG-STMTL-based** throughout; it is not an exact reproduction of DG-STMTL and does not test its multi-task learning claim.

## Model and adjacency contract

`src/gnn/dg_stmtl_link.py` accepts only `history: [B,672,72]` in the caller-provided edge order and returns one `[B,72]` forecast for `origin+96`. It accepts no target argument. Dynamic adjacency is generated separately for each batch sample; no graph operation mixes batch samples. The static prior is 216×216 (three temporal slots × 72 directed-link vertices). It is the binary union of the documented same-slot spatial, adjacent-slot temporal, and adjacent-slot spatio-temporal links, with self loops. Dynamic and static adjacency are gated, normalized, and consumed by the same group graph operators. The residual head is zero-initialized, so initialization returns the fixed alpha-0.8 five-sample EWMA exactly.

Topology order remains the verified 72 directed-edge order. The local topology byte digest is an identity check only; upstream GEANT topology provenance remains unverified. The implementation does not change `src/gnn/model.py` or the existing model.

## Run lifecycle, persistence, and authorization

The new output namespace is `data/processed/geant_dg_stmtl_based_h96_v1/`, with one exclusive destination per seed: `dg_stmtl_topology_seed_{42,123,2026}`. The runner defaults to no action and requires both `--run-training` and `--authorize-dg-stmtl`; the notebook defaults `TRAINING_ENABLED = False` and requires a separate exact authorization phrase for each seed. An existing destination is an error; runs are never resumed or overwritten. Run metadata is written as incomplete before model construction, updated after epochs, and marked complete only after checkpoint hash verification, strict reload, full validation evaluation, prediction hash, and exact artifact inventory checks. Failure recording preserves the original exception; output is retained.

The Colab workflow requires the reviewed Linux v3 resource monitor, runs one seed at a time, and copies each completed run to a new persistent Drive child. Notebook preflight mounts Drive, requires the canonical `MyDrive` mount and an already-existing canonical parent directory, and checks that the versioned result destination is absent. The persistent copy is read-back hash-verified before another seed may begin. A failed/partial backup is retained and blocks retry into that destination. This preparation does not create or approve a source bundle and does not launch training. A separately reviewed source snapshot and expected hashes are required before notebook preflight can pass.

## Comparison report

`phase9_geant/compare_dg_stmtl_h96.py` accepts exactly nine explicit frozen GNN `run.json` paths (the 3 seeds × 3 adjacency modes) and three DG-STMTL-based `run.json` paths. It reads only these JSON manifests. It rejects incomplete/legacy/mismatched run identities, missing strict reload/test-denial declarations, unequal normalization, dataset metadata hash, edge digest, validation window count, or evaluated pair count. It writes CSV/JSON/Markdown into a previously nonexistent output directory. The report includes per-seed MAE/RMSE, mean ± sample SD, relative changes from EWMA, parameter counts, and training duration. It neither loads checkpoints nor reads saved prediction arrays. A comparison is not valid until all required manifests pass the same identity checks.
