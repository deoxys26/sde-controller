## Candidate designs (conditional; not an authorization to build or train)

Candidate A is a temporal-signal hypothesis motivated by Stage 8's descriptive long-lag autocorrelation; it is not yet supported as a useful forecasting intervention. Stage 9's predeclared training-only diagnostic rule below determines whether to recommend a new builder. Candidate B is **not justified** by current evidence and remains conditional on new, leakage-safe evidence of spatial signal.

### Candidate A — 24-hour seasonal input with per-link residual head

- Add the utilization at target index minus 96 steps (24 hours) to each link's existing five recent history values. Predict the next-step residual over the fixed alpha-0.8 EWMA baseline; reconstruct utilization as EWMA plus predicted residual. This uses six scalar features per link and no topology.
- If reconsidered after new evidence and separate approval, this feature requires a new versioned builder/window schema and a fresh train/validation-only output root; it must not reuse or overwrite v1 arrays or runs. This document does not authorize that builder.
- Require the recent five history points, target, seasonal lag, and every intervening observation from target-minus-96 through target to be valid, consecutive, and inside one official split. Validation windows may **not** borrow train-period observations as lag inputs: all inputs and the target must remain in the validation block. Thus early validation windows lacking the complete 96-step history are dropped. Windows without full lag history are unavailable; do not impute or pad.
- Compare EWMA, the retained v1 MLP residual, and every new model on the **same exact window/link set**. Recompute both EWMA and v1 MLP residual predictions on the reduced set; do not compare their old all-window aggregates. Record the original and retained window counts and the number dropped, by split and reason.
- Build/fingerprint the seasonal feature as a separate named train/validation array. Fit utilization, feature, and residual scalers on training examples only; freeze them for validation as in v1. Keep EWMA alpha fixed at 0.8 and compute it only from the latest five historical points. Every feature used for target index `q` must be derived from observations at indices strictly less than `q`; no input may use or follow its own target.

### Time-of-day alternative — per-link residual head

- Add hour-of-day sine and cosine features derived deterministically from the protocol's anchor timestamp, each window's target index, and `step_seconds`. This needs no longer history. A new raw-data builder is not inherently required because the train/validation provenance already carries the anchor, step, and window indices; however, if persisted features are used, write a separately named, fingerprinted side array under a fresh versioned output root. Compute features on the fly only from validated train/validation provenance. Use the same split-local and causal rules above.

### Candidate B — directed-link line-graph residual model (not currently justified)

- Represent each directed link as a line-graph node, with that link's five historical utilization values as its features. Connect links that share a router, including the reverse directed link. Predict one residual per target link and reconstruct over the same alpha-0.8 EWMA baseline.
- Do not proceed unless a separately approved training-only or validation-only audit first establishes a reproducible spatial signal. If that condition is met, compare actual line-graph adjacency with identity adjacency and deterministic shuffled-edge controls. Include the v1 per-link MLP residual as the model-to-beat. Use identical samples, feature scaling, target ordering, optimizer budget, seeds, and metrics for all arms.
- The same-window neighbor-residual statistic above is strictly descriptive and must never be supplied as an input. The causal signal is the historical-neighbor-utilization statistic only.

## Protocol proposal — freeze before any future run

- Seeds: 42, 123, and 2026. Use a new version suffix and distinct destinations, for example `neural_ewma_residual_v2_candidate_a_seed_{42,123,2026}` and `neural_graph_residual_v2_candidate_b_seed_{42,123,2026}`. Refuse existing destinations.
- Declared protocol change from v1: train at most **20 epochs** with **patience 4**, Adam learning rate 0.005, batch size 32, and seeds 42, 123, 2026. The larger budget is predeclared because v1 seed 2026 was still improving at its five-epoch cap; this is a protocol change, not an outcome-driven tuning decision. Training windows alone provide gradients; validation loss alone controls early stopping and checkpoint selection. No test access during development.
- Use `SmoothL1Loss(beta=0.1)` on residuals standardized with training-only statistics. The small beta keeps the loss near L1 for most standardized residual magnitudes while remaining smooth around zero. If the head predicts standardized `(residual - train_mean) / train_scale`, zero weights **and zero bias** reconstruct the training-mean residual, not exactly EWMA. To initialize exactly at EWMA, set output weights to zero and initialize the output bias to `-train_mean / train_scale`; after inverse scaling this produces zero residual. Freeze this convention before training. Initialization is not evidence of improved performance.
- Primary metric: original utilization-ratio MAE over identical finite validation window-link pairs. Secondary metric: RMSE. Report all seeds, per-seed and aggregate values, coverage, and paired errors. Do not use training metrics as a selection gate.
- **Predeclared usefulness gate (all conditions required):** (1) per-seed relative MAE reduction versus EWMA is at least 1% in at least two of three seeds; (2) the arithmetic mean of the three seed-level relative reductions is at least 1%; and (3) a paired block-bootstrap interval for `candidate MAE - v1 MLP residual MAE` on identical windows has its 95% CI wholly below zero. Resample aligned contiguous 96-step (24-hour) validation blocks, retaining all directed links and paired model errors within each block; never join blocks across invalid gaps or split boundaries. Declare a **192-step (48-hour)** block length as the sole sensitivity analysis in advance. Report eligible blocks/windows for both lengths. If a fixed block scheme cannot be formed, do not substitute an iid/window bootstrap; request protocol review. The v1 MLP is the comparator, not a tuned baseline.
- This is validation-only evidence. The test split remains sealed until one model is frozen, the protocol and artifacts are reviewed, and a separate one-time final-evaluation approval is granted.

## Stage 9 training-only decision rule (written before the diagnostic)

The standalone Stage 9 diagnostic evaluates no validation data and fits no forecasting model; its chronological ridge is a fixed-alpha signal diagnostic on training data only. Before running it, the decision thresholds are fixed: if the best allowed feature set's chronological held-out MAE reduction versus alpha-0.8 EWMA is **below 0.5%**, Candidate A is unsupported and the recommendation is to stop without proposing a v2 builder; if the reduction is **at least 1.0%**, the feature family carrying the gain may justify proposing a new train/validation-only builder for review; if it is **at least 0.5% but below 1.0%**, report the result and request direction. These thresholds are diagnostic decision rules, not the later neural-model usefulness gate above. No threshold or feature set may be changed after seeing results.

## Integrity tests required before any run

1. Seasonal target/lag alignment proves seasonal index is exactly target-minus-96 and every feature index is strictly earlier than the target.
2. Window construction rejects invalid observations, chronology gaps, and all train/validation/test boundary crossings across the entire seasonal span.
3. Train-only scaling is invariant to changed validation fixtures; no missing value is imputed or clipped.
4. Provenance binds the new builder/protocol ID, exact split-local start and target indices, feature ordering, array fingerprints, and topology ordering where applicable.
5. Candidate B tests verify line-graph node-to-directed-link mapping, identity control behavior, deterministic shuffled adjacency, and preserved declared degree constraints.
6. Paired block bootstrap tests keep candidate and v1 predictions aligned, resample only contiguous validation blocks, and are deterministic under the fixed seed.
7. Read guards reject any test-array read; output tests refuse existing v2 paths and prove train/validation-only artifacts do not include test arrays or test-derived rows.
