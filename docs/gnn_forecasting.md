# Phase 4: Synthetic Link-QoS Forecasting

## Implementation facts

Phase 4 forecasts QoS from **synthetic network telemetry generated by this project's discrete-time network simulator**. UNSW-NB15 is not an input to this model.

The input is a sequence of directed NetworkX-topology snapshots. Every topology edge is retained in a stable directed edge order. Each edge has the Phase 3 fields `capacity`, `traffic`, `utilization`, `queue_length`, `delay`, `packet_loss`, `jitter`, and `throughput`. The prediction targets are the next-timestep edge `delay`, `utilization`, `packet_loss`, and `jitter`.

For a history length `H` and horizon `P`, a sample consists only of snapshots `[t-H+1, ..., t]` and target values at `t+P`. The implementation rejects insufficient history and constructs samples in sorted timestep order. Therefore target telemetry is never part of its own input.

The default configuration is `H=5`, `P=1`, with a chronological 70% / 15% / 15% time-period split. The feature scaler is fit only to all edge rows at or before the training-period boundary; validation and test values cannot influence its mean or standard deviation. Tests also confirm that mutating future rows does not change an existing training input.

## Model and training

Each snapshot uses two small directed graph-convolution layers over the topology. (The active Python environment does not provide PyTorch Geometric, so the implementation uses a transparent PyTorch mean aggregation over incoming directed neighbours.) The embeddings of a link's source and destination are concatenated with its normalized edge telemetry, producing an edge representation. The per-link historical representations are fed to a GRU and an MLP head emits the four normalized future QoS values. Training uses seeded PyTorch, Adam, Smooth L1 loss, validation checkpoint selection, and MAE/RMSE evaluation after inverse scaling.

The required non-ML comparison is persistence: the last observed link QoS values are used unchanged as the next-timestep prediction. Experiments must report measured test MAE/RMSE for both models without assuming the GNN wins.

## Research hypotheses and limitations

The hypothesis is that topology-aware historical dynamics can improve link-QoS forecasts over persistence. This is not an implementation result and must be tested per experiment. The model is CPU-friendly but intentionally small; it does not include attention, traffic classes, packet-level dynamics, real-world telemetry, external validation, or security/anomaly features. Synthetic-only results must not be generalized to production networks or described as research novelty.
